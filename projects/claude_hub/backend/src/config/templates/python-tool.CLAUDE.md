## 记忆（最重要）
- 根目录维护 `mem.md`。**每次任务前先读，完成后把进展/方案取舍/踩坑写回**（写清「改了什么、为什么、怎么验证」）。

## 技术栈与环境
- Python 3.10+。使用**虚拟环境**（`venv` / `uv` / `poetry` 任一），依赖锁定在 `requirements.txt` 或 `pyproject.toml`，不污染全局环境。
- 全量 **type hints**，用 `mypy` / `pyright` 静态检查；用 `ruff` / `black` 统一格式与 lint。

## 启动与部署（强制：pm2 + 端口自检 + 先构建再启动）
- 需要长驻的服务（API / 定时任务 / Web 界面）**一律用 pm2 启动**（`pm2 start ecosystem.config.js`，解释器指向虚拟环境里的 python），禁止拿裸 `python xxx.py` 前台跑当正式服务；`pm2 save` 保证机器重启后自动拉起。
- **端口必须先检测再用**，禁止盲目启动导致端口冲突、更禁止随手杀掉占用端口的别人的进程：
  - 代码里探测：`socket.socket().bind((host, port))` 捕获 `OSError`；命令行排查：Windows `netstat -ano | findstr :<port>`，Linux/macOS `lsof -i:<port>`。
  - 被占用时二选一并明确告知用户：**顺延到下一个可用端口**，或**报错退出并打印是谁占用了**。实际端口打印到日志并写入 `.runtime-port`。
- **每次启动默认走构建/校验后的产物**：先跑打包或 `mypy`/`ruff`/`pytest` 校验通过，再切换到新版本；产物先写临时目录、成功后再原子替换，失败保留旧版本继续服务——**开发中途的半成品不影响上一个正在使用的版本**。
- 每次开发完主动告诉用户**哪些服务需要重启、具体命令是什么**。

## 架构（松耦合分层）
- 分层清晰、互相通过清晰接口通信，避免一个函数既解析参数、又读写文件、又打印结果：
  - **入口/CLI**：只解析参数与编排流程（`argparse` / `click`）。
  - **核心逻辑**：纯函数优先，可独立单测，不直接依赖 IO。
  - **IO/适配**：文件、网络、数据库等副作用集中在边界层。
- **松耦合、高内聚 + 复用优先**：能用已有工具函数完成的先复用，不重复造轮子。

## 日志与错误处理
- 用标准 `logging`（带级别与开关），**不散落 `print` 调试**；异常统一在边界处理并给出可读信息，便于日后接告警。
- 每个函数入口校验非法输入（空值、越界、类型不符），抛出的错误信息带上「函数名 + 非法值」。

## 质量
- 关键逻辑写 `pytest` 单测；纯函数尤其要覆盖边界。
- 跨平台：路径用 `pathlib`，进程/shell 差异用 `sys.platform` 运行时判断，不写死单一平台。
